# GigaAM Zoom Transcriber

Локальное Windows-приложение для **личного тестирования** Zoom Meetings → RTMS →
GigaAM Multilingual 220M CTC. Интерфейс на русском, языки распознавания: казахский,
русский и английский. Внешнее облачное STT и LLM не используются.

**Статус: реализация для Local Test, реальная Zoom-встреча ещё не проверена.**
Прохождение тестов протокола и локального распознавания не подтверждает доставку
RTMS или корректность реальной встречи. Результаты и границы
доказательств — [TESTING.md](docs/TESTING.md).

В личном General App (Development) уже подтверждена настройка **WebSocket** для
событий RTMS Started / Stopped / Interrupted; все три события сохранены в подписке.
Это предпочтительный локальный путь: внешний HTTPS endpoint и туннель не нужны.
На реальном сервисе Zoom проверены OAuth/PKCE, профиль подключённого аккаунта и
авторизация Event WebSocket (`build_connection: success`). С настройкой
IPv6/IPv4 fallback одно подключение заняло 0,97 с. Lifecycle event из встречи и
аудио ещё не получены; RTMS Start не выполнялся, списания не разрешены.
[Обезличенные результаты](docs/evidence/zoom-local-test.json).

## Как это выглядит в Zoom

Отдельного участника-бота нет. Вы входите в встречу обычным клиентом Zoom;
собственный General App получает разрешённый Zoom RTMS audio stream. Zoom
показывает обработку содержания приложением в Active Apps и уведомлениях.
Хост может запретить или остановить доступ. RTMS требует **Developer Pack credits**;
Developer-лицензия не подтверждает бесплатный доступ. Точная цена вашего аккаунта
до реального запуска должна быть проверена в Zoom Billing и явно принята вами.

Это не Enterprise-развёртывание и не опубликованное Marketplace-приложение.
Не включайте auto-start, автопополнение и организационную установку. Публичен
только исходный код на GitHub; ключи, SQLite, аудио и документы остаются у вас.

## Короткий запуск из IDE

Нужны Windows x64, Python 3.12 x64 с Tcl/Tk, Git и свободное место для CPU Torch
и модели. EXE не требуется. Откройте папку проекта в VS Code или PyCharm.

```powershell
git clone https://github.com/AssylbekGizatov/gigaam-zoom-transcriber.git
cd gigaam-zoom-transcriber
./setup.ps1
```

Если политика Windows запрещает сценарий, не отключайте защиту. Выполните в
терминале IDE команды из `setup.ps1` отдельно либо обратитесь к администратору.
Выберите интерпретатор `.venv/Scripts/python.exe` и запустите **app.py** с рабочей
папкой в корне проекта. Последующие запуски: `./start.ps1` или Run app.py в IDE.

Модель можно выбрать из существующей локальной папки вашего GigaAM-приложения
(она читается без изменения). Для отдельной копии загрузите закреплённые веса:

```powershell
./.venv/Scripts/python.exe scripts/acquire_model.py
```

Это явная загрузка при настройке. Во время сеанса недостающая модель вызывает
ошибку, автоматической загрузки и `trust_remote_code` нет. Перед загрузкой
проверяются SHA256 config и весов. [Происхождение и лицензии](NOTICE.md).

## Разовые действия в Zoom

Полный порядок и точные scopes: **[ZOOM_SETUP.md](docs/ZOOM_SETUP.md)**.

1. Создать собственный **user-managed General App**, оставить в **Local Test**.
2. Настроить только четыре согласованных scopes из инструкции, Public Client OAuth
   (PKCE) и `http://127.0.0.1/callback`. PKCE уже включён в личном тестовом приложении.
3. В Access → Event subscriptions выбрать **WebSocket**, сохранить RTMS Started /
   Stopped / Interrupted и скопировать выданный Zoom Endpoint URL только локально.
4. Во вкладке «Разовая настройка» выбрать доставку `websocket`; внести Client ID,
   Public Client ID, Client Secret, WebSocket Endpoint URL и путь модели.
   «Сохранить настройки» → «Проверить события Zoom». Эта проверка подтверждает
   авторизацию канала событий и не запускает RTMS. Секреты шифруются Windows DPAPI.
5. Подключить Zoom через официальный браузер, самому подтвердить показанные
   разрешения. Проверить Developer Pack, цену, баланс и условия списаний.

Webhook с подписанными HTTPS-запросами оставлен резервным режимом. Для него нужен
отдельно выбранный и согласованный forwarder; при WebSocket он не используется.
Согласование scopes и подписки не разрешает запуск RTMS или расход кредитов.

Zoom-коннектор для чтения материалов встреч не заменяет Developer Marketplace
и не выдаёт приложению RTMS credentials. Пароль Zoom этому приложению не нужен.

## Ежедневное использование

1. Запустить приложение с доставкой событий `websocket`. После изменения
   credentials/подписки можно нажать «Проверить события Zoom» без старта RTMS.
2. Войти обычным Zoom-клиентом в свою тестовую встречу. Вставить ID/ссылку либо
   выбрать «Мои встречи». Ссылка не даёт права доступа к чужой встрече.
3. Выбрать локальную папку сеанса. Уведомить участников, получить необходимые
   разрешения и подтвердить расход кредитов **только для этого сеанса**.
4. Нажать «Начать». Дождаться статуса индивидуального аудио; только это означает
   установленное медиа-соединение. При нехватке CPU виден пропуск аудио.
5. Нажать «Стоп и завершить текст», дождаться обработки очереди и экспортировать
   TXT / Markdown / DOCX / PDF / JSON. Если Zoom не подтвердил Stop, остановить
   приложение в **Active Apps** встречи и проверить Developer Billing.

SQLite — встроенный локальный файл журнала в выбранной папке, без сервера БД.
Он сохраняет реплики постепенно и позволяет открыть сеанс после перезапуска.
Окно содержит только последние 500 реплик; полный текст доступен экспорту.
По умолчанию исходное аудио на диск не записывается. SQLite не шифрует разговор:
защитите локальную папку обычными средствами Windows; OneDrive может её синхронизировать.

## Участники и время

Реплика содержит `id`, `speaker_id` (реальный RTMS user_id), `display_name`,
`source_epoch`, `start`, `end`, `text`, `status` (`preliminary` / `final`). CTC
декодирует завершённые окна и публикует финальный текст; предварительная
пословная гипотеза не симулируется. JSON сохраняет схему, участников и пропуски.

Имя не является идентификатором: одинаковые имена различаются по Zoom ID.
Переименование не переписывает старые реплики. Повторный вход и переподключение
получают отдельную эпоху источника. Соединение одного источника с личностью
человека после повторного входа не угадывается. Общий микрофон остаётся одним
источником. ID `0` обозначает смешанный звук; разделение людей и имена по голосу
не выдумываются. Исследование диаризации и альтернатив — [ZOOM_RESEARCH.md](docs/ZOOM_RESEARCH.md).

Таймкоды вычисляются из server timestamp Zoom и word timestamps GigaAM. RTMS
первый timestamp описывает начало RTMS-сессии. При позднем включении это нельзя
выдавать за начало всей встречи: интерфейс и JSON указывают `time_basis`.
Без первого timestamp используется явно помеченное начало первого аудио.
Абсолютный origin сохраняется в JSON, переподключение часы не обнуляет.
Если нужно время от начала всей встречи при позднем подключении, укажите
фактическое начало в поле интерфейса (ДД.ММ.ГГГГ ЧЧ:ММ:СС, UTC+05:00).
Приложение сохраняет, что origin введён пользователем; запланированное время
встречи не подставляется вместо фактического. Аудио до запуска RTMS не восстанавливается.
