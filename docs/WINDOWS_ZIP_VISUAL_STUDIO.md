# Запуск из ZIP на Windows через Microsoft Visual Studio

Эта инструкция для первого запуска, даже если ты раньше не работал с Python.
Проект скачивается кнопкой **Download ZIP**, без клонирования репозитория.
В конце откроется отдельное окно **«GigaAM · Живой текст Zoom»**.

**Короткий порядок:** установить Python и Git → распаковать ZIP → открыть папку
в Visual Studio → выполнить команды установки → скачать модель → запустить
`app.py` → выбрать звук и папку текста → «Начать».

Инструкция относится к основному локальному приложению `app.py` в версии
репозитория от 3 ноября 2026 года. **`app_rtms.py` не запускаем:** это отдельный
старый режим, который требует настройки Zoom и может расходовать Zoom credits.

## 1. Что нужно установить один раз

- **Windows 10/11 x64**, обычный компьютер с Intel/AMD. Этот путь не рассчитан
  на macOS, Linux/WSL или нативный Python ARM64.
- **Python именно 3.12, 64-bit, с Tcl/Tk**. Версии 3.13 и новее сейчас не подходят
  под требования проекта. Tcl/Tk нужен для окна приложения.
- **Git for Windows**. Он понадобится установщику одной зависимости.
  Скачивать сам проект через Git, создавать аккаунт GitHub или выполнять
  команду клонирования не нужно.
- **Microsoft Visual Studio с поддержкой Python** либо **Visual Studio Code**.
  Это две разные программы; ниже есть отдельные шаги для каждой.
- Интернет для первоначальной установки библиотек и загрузки модели.
  Для локального распознавания после установки интернет не нужен, но обычный
  звонок Zoom по-прежнему требует своего соединения.

Для первого опыта желательно иметь 8 ГБ ОЗУ или больше и несколько свободных
гигабайт на диске. Это практический ориентир, а не гарантия скорости.
Видеокарта NVIDIA, CUDA, Node.js, Docker, отдельная база данных и FFmpeg для
основного живого режима не нужны: в коде используется CPU.

### Python

1. Если Python 3.12 x64 уже установлен, пока ничего не переустанавливай:
   сначала выполни проверки из раздела 4.
2. Если его нет, начни с [официальной страницы Python для Windows](https://www.python.org/downloads/windows/).
   Установи официальный **Python install manager**. Затем открой PowerShell
   через меню «Пуск» и установи нужную ветку:
   ```powershell
   pymanager install 3.12
   ```
   Эта команда относится именно к новому install manager. Старый Python Launcher
   не умеет устанавливать версии. [Официальное описание менеджера](https://docs.python.org/3/using/windows.html#python-install-manager).
3. Если пользуешься классическим установщиком Python, выбирай **Windows installer
   (64-bit)** для 3.12, не `embeddable package` и не 32-bit. В установщике должны
   быть включены **pip**, **tcl/tk and IDLE** и **Python Launcher**. Если есть
   галочка добавления Python в PATH, её можно включить.
4. Закрой и заново открой терминал/Visual Studio после установки. Проверки
   версии, разрядности и Tcl/Tk ниже обязательны.

### Git

Установи [Git for Windows с официального сайта](https://git-scm.com/downloads/win).
В установщике оставь вариант, при котором Git доступен из командной строки
и сторонних программ. Затем перезапусти Visual Studio и её терминалы.

**Почему Git нужен при работе через ZIP?** В `requirements-asr.txt` пакет GigaAM
указан ссылкой `git+https` на конкретную версию исходников. `pip` сам использует
Git для этой библиотеки. ZIP заменяет только скачивание **нашего проекта**.
Полностью без установленного Git текущий стандартный способ установки не работает.

### Visual Studio или VS Code

- **Microsoft Visual Studio**: большая IDE, обычно с фиолетовым значком.
  В **Visual Studio Installer → Modify / Изменить** отметь
  **Python development / Разработка на Python** и установи компоненты.
  Наличие только C++/.NET-компонентов не даёт поддержки Python.
  [Инструкция Microsoft](https://learn.microsoft.com/en-us/visualstudio/python/installing-python-support-in-visual-studio?view=visualstudio).
- **Visual Studio Code**: отдельный редактор, обычно с синим значком.
  Если установлен он, используй раздел 8. Две IDE одновременно устанавливать
  не требуется.

## 2. Скачать ZIP и правильно распаковать

1. Открой [репозиторий gigaam-zoom-transcriber](https://github.com/AssylbekGizatov/gigaam-zoom-transcriber).
2. Убедись, что выбрана ветка **main**.
3. Нажми зелёную кнопку **Code → Download ZIP**.
4. В проводнике Windows найди скачанный `gigaam-zoom-transcriber-main.zip`.
   Нажми правой кнопкой → **Извлечь всё / Extract All**.
5. Помести извлечённую папку в удобное постоянное место, например:
   ```text
   C:\Users\ТвоёИмя\Projects\gigaam-zoom-transcriber-main
   ```
   Лучше не использовать `Program Files`, сетевой диск и синхронизируемую
   папку OneDrive. Для установки в свою папку запуск от администратора не нужен.
6. Открой извлечённую папку. **Внутри неё сразу должны быть**:
   ```text
   app.py
   app_rtms.py
   setup.ps1
   start.ps1
   requirements-desktop.txt
   constraints.txt
   gigaam_zoom\
   scripts\
   docs\
   ```

Это и есть **корень проекта**. Если видишь только ещё одну папку
`gigaam-zoom-transcriber-main`, зайди внутрь неё.
Не запускай файлы прямо из просмотрщика ZIP.

В ZIP пока **нет** `.venv` и больших файлов модели. Их создадут следующие шаги.
Не перемещай папку проекта после создания `.venv`: окружение привязано к пути.

## 3. Открыть папку в Microsoft Visual Studio

1. Запусти Visual Studio.
2. На стартовом экране выбери **Open a local folder / Открыть локальную папку**.
   В уже открытой IDE: **File → Open → Folder / Файл → Открыть → Папка**.
3. Выбери именно корень, где лежит `app.py`.
4. В **Solution Explorer / Обозревателе решений** появятся файлы.
   Создавать новый C++, C# или веб-проект не нужно. Файлов `.sln` и `.pyproj`
   в репозитории нет; для Python поддерживается открытие обычной папки.
5. Открой **View → Terminal / Вид → Терминал**. Выбери профиль PowerShell
   или Developer PowerShell. Если такого пункта нет, открой PowerShell из «Пуска»:
   все команды ниже работают и вне IDE.

Не используй для этих команд окно **Python Interactive** с приглашением `>>>`
или консоль управления NuGet. Нужен именно **PowerShell**.

[Открытие папки и запуск Python в Visual Studio](https://learn.microsoft.com/en-us/visualstudio/python/quickstart-05-python-visual-studio-open-folder?view=vs-2022).

## 4. Перейти в корень и проверить программы

Команды выполняй **по одной**: вставь строку, нажми Enter, дождись окончания.
Копируй только саму команду, без рамки блока и без слова `powershell`.
Если появилась ошибка, не переходи к следующему шагу установки.

В проводнике открой корень проекта, нажми **Ctrl+L**, затем **Ctrl+C**:
это копирует полный путь. В терминале введи `Set-Location -LiteralPath`,
после него путь в кавычках. Например, если распаковал в указанное выше место:

```powershell
Set-Location -LiteralPath "$HOME\Projects\gigaam-zoom-transcriber-main"
```

`$HOME` означает папку твоего пользователя Windows. Если распаковал в другое
место, замени весь путь в кавычках своим. Проверь:

```powershell
Get-Location
Test-Path .\app.py
Test-Path .\requirements-desktop.txt
```

Обе команды `Test-Path` должны вывести **True**. Затем:

```powershell
py -3.12 --version
py -3.12 -c "import struct, platform; print(struct.calcsize('P') * 8, platform.machine())"
git --version
py -3.12 -m tkinter
```

Что должно получиться:

- `Python 3.12.x`;
- `64 AMD64` или эквивалентное обозначение x64;
- строка `git version ...`;
- небольшое тестовое окно Tcl/Tk. Закрой его перед продолжением.

Если видишь `32`, `ARM64`, другую ветку Python или ошибку Tcl/Tk, сначала исправь
установку. Полный основной сценарий ниже предполагает Python 3.12 x64.

## 5. Установить библиотеки проекта

Здесь используется тот же порядок, что в `setup.ps1`, но команды вводятся
напрямую. Это позволяет обойтись **без запуска PowerShell-скриптов и без
изменения политики безопасности Windows**.

### 5.1. Создать отдельное окружение

```powershell
py -3.12 -m venv .venv
```

Появится папка `.venv`. В ней будут Python и библиотеки только этого проекта.
Проверь:

```powershell
.\.venv\Scripts\python.exe --version
```

Должно быть `Python 3.12.x`.

**Активировать окружение не нужно.** Во всех дальнейших командах указан полный
относительный путь `.\.venv\Scripts\python.exe`. Он надёжнее, чем просто `python`
или `pip`, которые могут относиться к другой установке.

### 5.2. Установить CPU-версию PyTorch

Скопируй следующую длинную строку целиком как **одну команду**:

```powershell
.\.venv\Scripts\python.exe -m pip install --index-url https://download.pytorch.org/whl/cpu torch==2.10.0+cpu torchaudio==2.10.0+cpu -c constraints.txt
```

Дождись, пока снова появится приглашение PowerShell. Загрузка может занять
несколько минут и больше в зависимости от соединения.

### 5.3. Установить остальные библиотеки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-desktop.txt -c constraints.txt
```

Здесь установятся GigaAM, библиотеки интерфейса/экспорта и Windows-захвата звука.
Строки загрузки, сборки пакетов и обращения Git к исходникам GigaAM нормальны.
Но сообщение `ERROR` означает, что сначала надо разобраться с установкой.

Не меняй версии и не убирай `-c constraints.txt` наугад.
Не используй `pip install -r requirements.txt`: файла с таким именем здесь нет.

### 5.4. Проверить зависимости

```powershell
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -c "import tkinter, torch, torchaudio, gigaam, pyaudiowpatch, comtypes; print('IMPORTS OK')"
```

Ожидается `No broken requirements found.` и `IMPORTS OK`.
Это проверка установки библиотек, **не проверка реальной встречи Zoom**.

Если предпочитаешь штатный установочный скрипт, `.\setup.ps1` выполняет шаги
5.1–5.3. Не нужно делать оба способа подряд. Если Windows блокирует `.ps1`,
используй команды выше: `Set-ExecutionPolicy`, `Bypass` и запуск IDE
от администратора для этого не нужны.

## 6. Скачать модель распознавания

Оставайся в том же терминале и в корне проекта:

```powershell
.\.venv\Scripts\python.exe scripts\acquire_model.py
```

Это отдельная загрузка весов GigaAM Multilingual. Скрипт обращается к
Hugging Face и GitHub, проверяет SHA256 и создаёт:

```text
models\gigaam\config.json
models\gigaam\pytorch_model.bin
models\gigaam\LICENSE
models\gigaam\provenance.json
```

**У этой команды нет индикатора процентов.** Пустой терминал во время скачивания
сам по себе не означает зависание. Дождись возврата приглашения PowerShell.
При сетевой ошибке прочитай её, затем повтори команду после восстановления связи.

Проверка файлов и их контрольных сумм:

```powershell
.\.venv\Scripts\python.exe -c "from gigaam_zoom.engine import verify_model; verify_model('models/gigaam'); print('MODEL OK')"
```

Должно появиться `MODEL OK`. Произвольные другие веса GigaAM не подойдут:
приложение принимает конкретную проверенную версию.

**Для первого запуска различение голосов можно пропустить.**
Если позже нужны подписи «Говорящий 1, 2…», дополнительно выполни:

```powershell
.\.venv\Scripts\python.exe scripts\download_diarization.py
```

Это загрузит необязательную проверенную CAM++-модель размером около 28 МБ:
`models\diarization\campplus.onnx`. Само скачивание ещё не включает функцию
в интерфейсе.

### Ключи, .env и аккаунты

Для **`app.py`** не нужны Zoom Client Secret, OAuth-токены, API-ключи,
Hugging Face token, `.env` или ручные переменные окружения.
Не добавляй секреты в исходники и не загружай их на GitHub.
Параметры локального режима выбираются в окне приложения.

## 7. Первый запуск и настройка окна

Сначала запусти через терминал, чтобы видеть возможную ошибку:

```powershell
.\.venv\Scripts\python.exe app.py
```

Должно открыться отдельное окно **«GigaAM · Живой текст Zoom»**.
Это не сайт: открывать `localhost` или искать порт в браузере не надо.
Отдельная команда Build/Rebuild и сборка `.exe` для запуска исходников не требуются.

Пока окно работает, терминал занят. Это нормально. Не закрывай его принудительно.

### Что выбрать в приложении

1. В проводнике создай папку для результатов, например
   `C:\Users\ТвоёИмя\GigaAM-Results`. Папка должна **уже существовать**
   и находиться на локальном диске.
2. На вкладке **«Модель и помощь»** нажми **«Выбрать папку…»** и укажи
   `models\gigaam` внутри проекта. Выбирается **папка**, не файл `.bin`.
3. На вкладке **«Встреча»** в строке **«Папка текста»** выбери созданную папку.
   Для приватных разговоров выбирай место вне OneDrive/другой синхронизации:
   само приложение папку не шифрует.
4. Для первого опыта оставь **«Различать голоса локально…»** выключенным.
   Если скачал CAM++, на вкладке «Модель и помощь» выбери файл
   `models\diarization\campplus.onnx` и затем включи эту опцию на вкладке встречи.
5. После выбора **обеих папок**, модели и результатов, можно нажать
   **«Сохранить настройки»**. Без папки результатов сохранение выдаст ошибку.
6. Открой обычный **Zoom Workplace**, войди во встречу и подключи компьютерный звук.
   В настройках Zoom посмотри выбранный **динамик / Speaker**.
7. В приложении в списке **«Звук Zoom»** выбери **тот же физический выход**:
   например, те же наушники. Если менял устройство, нажми «Обновить устройства»
   до начала сеанса.
8. Если нужен также твой голос, включи **«Добавить мой микрофон»**, выбери
   микрофон и заполни «Моё имя». По умолчанию микрофон выключен.
9. Уведоми участников о транскрипции и соблюдай требования согласия.
   Нажми **«Начать»** заранее.
10. Дождись статуса **«Идёт локальная транскрипция»**.
    Во время «Загрузка локальной модели…» звук ещё не принимается.
    Текст появляется фразами с задержкой, а не мгновенно по каждому слову.
11. После разговора нажми **«Стоп и завершить текст»** и дождись завершения.
    Выбери формат, например **DOCX**, нажми **«Экспорт полного текста…»**
    и выбери папку экспорта.

Для короткой проверки до важной встречи можно воспроизвести публичный речевой
ролик через выбранные наушники, запустить захват и проверить появление текста.
Такой тест проверяет системный звук, но не доказывает совместимость всех
функций с твоей реальной встречей Zoom.

### Важные особенности

- Захватывается **весь звук выбранного выхода**, включая музыку и уведомления
  других приложений. Перед встречей выключи лишнее.
- Включённый в приложении микрофон продолжает обрабатываться **даже при Mute
  в Zoom**. Чтобы прекратить локальную обработку, останови её в приложении.
- Лучше использовать наушники, иначе микрофон может повторно слышать собеседников.
- Имена «по окну Zoom» и номера «по голосу» приблизительные. Неизвестный
  говорящий не означает, что распознавание текста сломалось.
- Приложение не сохраняет аудио/видео. Оно должно работать во время нужной части
  разговора: пропущенную речь после звонка восстановить не сможет.

## 8. Настроить запуск кнопкой в своей IDE

Окружение и модель уже должны быть готовы после разделов 5–6.
Закрой ранее открытое окно приложения перед повторным запуском.

### Microsoft Visual Studio

1. В обозревателе файлов нажми правой кнопкой по **`app.py`** →
   **Set as Startup Item / Назначить запускаемым элементом**.
2. В списке окружений Python на панели IDE выбери **`.venv` этого проекта**.
   Нужен интерпретатор:
   ```text
   <папка проекта>\.venv\Scripts\python.exe
   ```
3. Если его не видно: **View → Other Windows → Python Environments**
   → **Add Environment → Existing environment → Custom**.
   Укажи `<папка проекта>\.venv` как базовую папку окружения и проверь,
   что **Interpreter path** заканчивается на `.venv\Scripts\python.exe`.
   Нажми **Add / Добавить**, затем выбери это окружение в панели запуска.
   [Как добавить существующее окружение](https://learn.microsoft.com/en-us/visualstudio/python/managing-python-environments-in-visual-studio?view=vs-2022#manually-identify-an-existing-environment).
4. Рабочая папка должна быть **корнем проекта**, где `app.py` и `models`.
   При открытии именно этой папки и выборе корневого `app.py` это стандартное
   поведение Visual Studio. Не ставь рабочей папкой `gigaam_zoom` или `scripts`.
5. Выбери **Debug → Start Without Debugging / Отладка → Запуск без отладки**
   или нажми **Ctrl+F5**.

Названия пунктов могут немного отличаться в версиях и языках IDE.
Если команды Python отсутствуют, проверь установленную рабочую нагрузку
**Python development**. Если кнопка запуска выбирает не тот интерпретатор,
терминальная команда из раздела 7 остаётся правильным способом запуска.

### Visual Studio Code

Если у тебя именно VS Code, а не большая Visual Studio:

1. **File → Open Folder** → корень с `app.py`.
2. В **Extensions / Расширениях** установи **Python от Microsoft**.
3. **Ctrl+Shift+P → Python: Select Interpreter** → выбери
   `.venv\Scripts\python.exe`. Если его нет в списке, укажи путь вручную.
4. Открой `app.py` и выбери **Run Python File in Terminal**.
   Не выбирай «Run Selection» и не запускай внутренний
   `gigaam_zoom\desktop_gui.py` как отдельный файл.
5. Либо открой **Terminal → New Terminal**, выбери PowerShell, перейди в корень
   и используй команду из раздела 7.

[Выбор интерпретатора в VS Code](https://code.visualstudio.com/docs/python/environments).

## 9. Что делать при каждом следующем звонке

**Заново устанавливать библиотеки и скачивать модель не нужно.**

1. Открой распакованную папку в IDE.
2. Запусти `app.py` с `.venv` через кнопку IDE или из PowerShell:
   ```powershell
   Set-Location -LiteralPath "$HOME\Projects\gigaam-zoom-transcriber-main"
   .\.venv\Scripts\python.exe app.py
   ```
   Если выбрал другой путь, используй его.
3. Проверь устройство вывода, микрофон и папку текста.
4. Открой Zoom, затем «Начать» и дождись рабочего статуса.
5. В конце «Стоп и завершить текст» → дождаться → экспорт.

Файл `start.ps1` тоже запускает это же приложение из `.venv`, но не устанавливает
зависимости и не скачивает модель. Если запуск `.ps1` заблокирован, используй
команду выше.

Полученный текст постепенно сохраняется в выбранной папке в файле
`zoom-local-....sqlite`. Это локальный журнал, не готовый Word-документ.
Чтобы получить `.docx`/`.pdf`, выполни экспорт. Позднее журнал можно выбрать
кнопкой **«Открыть прошлый сеанс…»** и экспортировать снова.
Окно показывает последние 500 реплик, экспорт включает весь сохранённый текст.

Настройки сохраняются отдельно от ZIP:
`%LOCALAPPDATA%\GigaAMZoom\desktop-settings.json`.
Если распаковываешь новую версию в другую папку, создай там новое окружение
и заново выбери правильную папку модели. Не копируй старую `.venv` между путями.
Текстовые журналы и результаты сохраняй отдельно от обновляемого проекта.

## 10. Если что-то не работает

### «py не является командой» или «No suitable Python runtime found»

Перезапусти терминал и IDE после установки. Проверь установку Python Launcher
или нового Python install manager и наличие **3.12 x64**.
Для нового manager команда `pymanager install 3.12` устанавливает эту ветку.
Не заменяй без проверки `py -3.12` просто на `python`.

### «git not found», «Cannot find command git»

Установи Git for Windows с доступом из командной строки, перезапусти IDE
и проверь `git --version`. После этого повтори неудавшуюся установку зависимостей.

### «requirements-desktop.txt не найден» или «can't open file app.py»

Открыта не та папка. Повтори раздел 4: `Test-Path .\app.py` и
`Test-Path .\requirements-desktop.txt` должны показать `True`.

### PowerShell блокирует setup.ps1 или Activate.ps1

Используй команды раздела 5 и прямой запуск `.\.venv\Scripts\python.exe`.
Активация окружения и изменение ExecutionPolicy не требуются.

### «No matching distribution found» или конфликт зависимостей

Сначала проверь, что `.\.venv\Scripts\python.exe --version` показывает 3.12,
а `py -3.12` имеет разрядность x64. Для PyTorch нужен именно CPU-индекс
из шага 5.2. Если версия и архитектура правильные, сохрани точное сообщение:
причиной может быть недоступный пакет или несовместимость зафиксированных версий.
Не отключай проверку сертификатов и не ставь случайные версии из советов в интернете.

### «ModuleNotFoundError: torch / gigaam / pyaudiowpatch / comtypes»

Либо установка не закончилась, либо IDE использует другой Python.
Запусти команду из раздела 7. Если так работает, исправь интерпретатор в IDE.
Если нет, повтори проверки и соответствующий шаг установки раздела 5.

### «No module named tkinter» или не открывается тестовое окно Tcl/Tk

Нужна полная установка CPython с Tcl/Tk, не embeddable-сборка.
В классическом установщике используй Modify и компонент **tcl/tk and IDLE**.
Затем снова проверь `py -3.12 -m tkinter`.

### «Модель не найдена» или «Выберите существующую папку модели GigaAM»

Выполни раздел 6 из корня проекта. В интерфейсе выбери папку, внутри которой
сразу лежат `config.json` и `pytorch_model.bin`, например
`...\models\gigaam`, не просто `...\models`.

### «failed SHA256» или «Файлы модели не совпали с проверенной версией»

Скрипт специально не перезаписывает существующие неверные файлы.
Сохрани старую папку и скачай модель в **другую, ещё не использованную** папку:

```powershell
.\.venv\Scripts\python.exe scripts\acquire_model.py --directory models\gigaam-fresh
```

После успешного окончания выбери `models\gigaam-fresh` в интерфейсе.
Не отключай проверку SHA256 и не подставляй другую модель вместо ожидаемой.

### «Выберите папку для текста и экспорта»

Создай папку в проводнике и выбери её на вкладке «Встреча».
Потом сохраняй настройки. UNC-путь и сетевой диск не поддерживаются.

### Окно открылось, но текста нет

Дождись статуса рабочего захвата. Сверь выход **Speaker** в Zoom
со списком «Звук Zoom» в приложении. Проверь, слышен ли звук и движется ли
индикатор «Выход». Для своего голоса отдельно включи микрофон.
Речь до начала захвата не появится задним числом.

### После подключения Bluetooth/USB-наушников звук пропал

Нажми «Стоп», дождись завершения, обнови устройства, выбери новый выход,
сверь его с Zoom и начни новый сеанс. Не меняй устройства посреди захвата.

### Твой голос отсутствует или реплики дублируются

Для собственного голоса включи «Добавить мой микрофон» и выбери устройство.
Если собеседники дублируются, используй наушники: приложение не устраняет
эхо от динамиков самостоятельно. При проблеме с доступом проверь разрешение
Windows на микрофон для настольных приложений.

### «Не определён» вместо имени

Это допустимый результат. Имена из окна Zoom и группировка по голосу
экспериментальные. После остановки выбери реплику и исправь имя вручную.
Для «Говорящий 1, 2…» дополнительно нужна CAM++ и включённая опция.

### Окно сразу закрывается или IDE ничего не показывает

Запусти из PowerShell по разделу 7. Сообщение останется в терминале.
Проверь, что запускается `app.py`, а не `app_rtms.py` и не внутренний модуль.

### «fatal: not a git repository» при check_publication.py

В ZIP нет истории Git. `scripts/check_publication.py` проверяет отслеживаемые
Git-файлы для разработчика/CI и не является шагом пользовательского запуска.
Для работы приложения его выполнять не нужно.

### Если нужна помощь

Сохрани текст ошибки и напиши, на каком шаге она появилась.
Полезны результаты `py -3.12 --version`, `git --version` и `pip check` из `.venv`.
Перед отправкой скриншота скрой секреты, личные пути и текст встреч.
Не отправляй сам журнал `.sqlite`, если он содержит приватный разговор.
