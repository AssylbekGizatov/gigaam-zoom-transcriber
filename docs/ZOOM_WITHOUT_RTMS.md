# Локальная расшифровка Zoom без RTMS

Этот режим работает после встречи. Дополнительная подписка, API-токены,
сервер и RTMS не нужны. [Локальная запись Zoom](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0076922)
доступна и на Basic, если запись разрешена политикой и организатором.

1. В настольном Zoom включите **Settings → Recording → Record a separate audio file for each participant**.
2. В разрешённой встрече выберите **Record to this Computer**. После завершения
   дождитесь конвертации записи.
3. Найдите папку **Audio Record** с отдельными M4A. Не добавляйте туда общий микс.
4. Из корня этого проекта выполните, подставив свои пути:

   ```powershell
   .\.venv\Scripts\python.exe scripts/import_zoom_recording.py "C:\Zoom\Meeting\Audio Record" "C:\Zoom\Transcript" --model-dir "C:\Models\gigaam" --ffmpeg "C:\Tools\ffmpeg.exe"
   ```

   Нужны установленное окружение проекта, локальная модель и [FFmpeg](https://ffmpeg.org/download.html).
   Родительская папка результата должна существовать, сама папка результата — быть новой.

5. Откройте TXT, MD, DOCX, PDF или JSON из результата. SQLite можно открыть кнопкой
   «Открыть локальный сеанс…» в Windows-программе.

Имена берутся из [названий файлов Zoom](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0064394)
и могут требовать ручной проверки, например если имя заканчивается цифрами.
Совпадающие имена различаются по ID дорожек. Это ID файлов, а не Zoom user IDs.
Время отсчитывается от начала каждой дорожки. Между дорожками порядок событий
не подтверждён; вывод не заменяет синхронизированную стенограмму всей встречи.
Людей, говорящих в один микрофон, импорт не разделяет.

Программа читает и распознаёт PCM порциями, не отправляет аудио наружу,
не меняет исходные M4A и не запускает Zoom. Если обработка оборвалась,
в выходной папке может остаться частичный SQLite; это не полный результат.
