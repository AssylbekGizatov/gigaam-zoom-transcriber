# Проверка и измерения

Состояние на 16 октября 2026 года: локальный движок и реальный конвейер обработки PCM проверены на публичной казахской, русской и английской речи. Это **не подтверждает работу на реальной Zoom-встрече**. Публичные примеры прочитанной речи и их искусственная склейка не представляют естественный разговор, переключение языков внутри фразы, шумные микрофоны или одновременную речь.

## Воспроизводимые автоматические проверки

Из корня проекта, в созданном окружении Python 3.12:

```powershell
python -m pytest -q
```

Последний полный локальный прогон: **78 тестов прошли**, 8,84 с. Это результат проверки текущей реализации, не свидетельство подключения к Zoom.

Тесты проверяют PCM16, отдельные источники Zoom, предел очереди, таймкоды и их происхождение, пропуски, повторы пакетов, reconnect/epoch, одинаковые имена, переименование и выход, отсутствие имени, ограничение памяти и корректную остановку. Отдельно проверяются журнал SQLite, настройки, локальные пути, подписи событий, OAuth/PKCE и редактирование секретов в диагностике, экспорт пяти форматов и исключительное создание файлов без перезаписи. Ошибки конвейера и перегрузка не выдаются за успешно распознанное аудио.

CI находится в `.github/workflows/ci.yml`. Unit-тесты используют контролируемые фиктивные ответы модели и протокола. Они не обращаются к аккаунту Zoom, не включают тарификацию и не подменяют интеграционную проверку с Zoom. Успех удалённого CI следует проверять по фактическому статусу workflow после публикации.

## Оборудование и методика

Windows 11, Intel Core i5-10300H 2,50 ГГц, 8 логических CPU, 7,84 GiB RAM; Python 3.12.3, PyTorch/Torchaudio 2.10.0 CPU, NumPy 2.2.6, GigaAM 0.2.0. Локальные веса GigaAM Multilingual 220M CTC проверены по закреплённым SHA256. У модели четыре CPU-потока. GPU и внешняя LLM не использовались.

`scripts/evaluate.py` запускает настоящий `Transcriber`, затем настоящий `Pipeline` с SQLite и `AudioPacket`, 100 мс PCM на пакет. Режим `burst` передаёт разрешённые данные быстрее реального времени и измеряет производительность. Режим `realtime` подаёт пакеты с реальной скоростью и измеряет задержку до callback готовой реплики. Эти задержки не включают Zoom, сеть и показ в GUI.

RSS измеряется с интервалом 50 мс через psutil, включая модель. Это выборочный пик рабочего набора, а не доказательство максимального потребления при любой нагрузке. CPU измеряется как изменение process user+system CPU time; machine CPU делится на восемь логических CPU. Замеры однократные на занятом пользовательском компьютере, без статистического доверительного интервала. Холодная загрузка модели измерена отдельно; RTF движка не включает загрузку.

Во время распознавания Python socket connections блокировались; зафиксировано **0 попыток**. Это проверка отсутствия случайного Python-сетевого запроса, не замена системного firewall-аудита нативных библиотек. Загрузка исходных публичных данных происходила отдельно до этой проверки.

## Полученные результаты

Итоговые отчёты после исправления границы окон: [burst с psutil](evidence/public-audio-final-burst.json) и [подача в реальном времени](evidence/public-audio-final-paced.json). Первоначальные [burst](evidence/public-audio-burst-fresh.json) и [подача в реальном времени](evidence/public-audio-paced.json) сохранены как диагностика обнаруженного дефекта. Ранний [отчёт без RSS](evidence/public-audio-burst.json) не содержит RAM из-за недоступного psutil в первоначальном окружении; для RAM используются только последующие отчёты.

| Пример | WER всего файла | Время движка | RTF движка | WER итогового потокового конвейера |
|---|---:|---:|---:|---:|
| KK, 9 слов | 0% | 1,643 с | 0,142 | 0% |
| RU, 26 слов | 0% | 1,456 с | 0,129 | 0% |
| EN, 17 слов | 0% | 0,670 с | 0,114 | 0% |

В первоначальном потоковом KK-примере обнаружено повторение слова `тақырып` на границе восьмисекундных окон. Перекрытие увеличено с одной до двух секунд с разделением владения таймкодами. Повтор исчез в повторном прогоне настоящей модели; регрессионные тесты используют фактические метки слов и проверяют сохранение настоящего `да да`. Удаление повторов только по совпадению текста не применяется.

Итоговая искусственная склейка даёт WER 3,85%: модель смешивает алфавиты в двух английских словах на границе языков (`миsтеr кuilter` вместо `mister quilter`). Это ограничение распознавания сохраняется в отчёте без исправления текста эвристикой или LLM. Нулевой WER отдельных файлов не означает нулевой WER смешанной речи.

Итоговый `burst` конвейер обрабатывает склейку за 4,416 с, RTF 0,148; CPU процесса 17,109 CPU-секунды, в среднем 48,43% мощности восьми логических CPU. Выборочный пик RSS 1913,67 MiB. Пропусков и потерянных пакетов нет; таймкоды находятся в диапазоне аудиоматериала, очередь после stop пуста. Разница времени между первыми и итоговыми прогонами не доказывает ускорение: нагрузка компьютера менялась.

При итоговой подаче в реальном времени первая реплика склейки появляется через 9,51 с. Задержка готовой реплики относительно её последнего распознанного слова составляет 1,49–2,93 с по отдельным примерам и склейке. Пик RSS склейки 1910,20 MiB, средний CPU всей сессии 9,00% машины; низкое среднее включает время ожидания очередных пакетов. Холодная загрузка заняла 13,40–13,45 с, пик RSS при загрузке около 1,85 GiB. Сумма длительности окон в диагностике конвейера включает перекрытие, поэтому для пользовательского RTF используется исходная длительность аудио, не сумма окон. RTF wall в paced-отчёте включает ожидание и около единицы; скорость вычислений оценивается по burst.

WER нормализует Unicode casefold, `ё` в `е`, удаляет пунктуацию и сохраняет цифры. Девять казахских слов, 26 русских и 17 английских недостаточны для оценки качества на реальных встречах. Данные могут пересекаться с обучением модели; независимость корпуса не установлена.

## Экспорт и длинные встречи

TXT, Markdown и JSON читают SQLite последовательно; тест включает 20 000 реплик и один проход генератора. JSON сохраняет численные таймкоды, source ID, имя, status, epoch, отдельный список наблюдавшихся участников, метаданные, пропуски и события join/rename/leave. TXT/Markdown и документы показывают идентификаторы и статусы рядом с репликами. Экспорт различает начало сессии RTMS, первый полученный аудиопакет и подтверждённое начало встречи через `rtms_session_seconds`, `first_audio_seconds`, `meeting_seconds`; отсутствие сведений не выдаётся за известное начало всей встречи.

Файлы создаются с `x`/`xb`. Существующий файл не изменяется, авария убирает только новый частичный файл. UNC, URI и сетевые диски отклоняются; экспорт требует выбранной существующей локальной папки. Из метаданных удаляются ключи секретов; содержание распознанной речи остаётся пользовательскими данными и автоматически не редактируется.

PDF встраивает DejaVu Sans. Двухстраничный тест с казахскими `Ә Ғ Қ Ң Ө Ұ Ү Һ І`, русским, английским, ID и событиями отрендерен Poppler; обе страницы визуально проверены после исправления переноса слов и разрыва между меткой и репликой. DOCX с Arial проверен структурно как OOXML с Unicode и ID, затем открыт установленным Microsoft Word через COM в режиме read-only и преобразован `ExportAsFixedFormat` в PDF. Poppler отрендерил обе страницы, обе визуально проверены: символы читаемы, наложений, обрезанного текста и оторванных от реплики меток нет. Этот проверенный путь использован после того, как штатный `render_docx.py` не нашёл `soffice.exe` в предоставленном runtime. Результат зафиксирован в [проверке экспорта](evidence/export-validation.json).

python-docx хранит дерево документа в памяти, ReportLab удерживает объекты страниц. Поэтому DOCX ограничен 2 миллионами символов, PDF — 1000 страницами; при превышении приложение предлагает TXT или JSON. Это явные пределы экспортера, журнал и продолжение встречи от них не зависят. Многочасовой soak-тест с настоящей моделью, множество одновременно активных говорящих и аппаратное потребление памяти всей GUI-сессии пока не измерены.

Отдельный [ускоренный soak](evidence/soak.json) проверил 8 часов синтетической
шкалы с fake ASR за 45,755 с: три чередующихся источника, 7200 сохранённых реплик,
0 отказов/потерь, максимум очереди 26 из 48 секунд, после Stop 0. RSS после
прогрева 34,539 → 34,641 MiB; наблюдаемый пик 38,703 MiB. Выборка GUI ограничена
500 строками. Размер SQLite после checkpoint 1,92 MB. Намеренные паузы между
чередующимися источниками журналируются как gaps и не являются потерей очереди.
Это подтверждает ограничение памяти журнала/конвейера, но не восемь часов
реального Zoom и не восемь часов непрерывной работы настоящей модели.

Повтор ускоренного теста: `python scripts/soak.py --help`.

## Повтор измерений

Подготовьте локальный JSON manifest с массивом `clips`. У каждой записи нужны `path`, `language`, `reference`, `sha256`, `source_url`, `license`, `attribution`. Дополнительные поля provenance попадают в отчёт, локальный `path` исключается. WAV: PCM16 mono 16 kHz, не более 20 секунд на пример и 40 секунд суммарно с паузами. Примеры эталонов и SHA256 находятся в машинных отчётах выше; приватные записи использовать не следует.

```powershell
python scripts/evaluate.py --manifest work/fixtures/manifest.json --model-dir models/gigaam --report work/burst.json --pace burst
python scripts/evaluate.py --manifest work/fixtures/manifest.json --model-dir models/gigaam --report work/paced.json --pace realtime
```

`--repeat 3` повторяет прямой вызов движка; путь отчёта должен быть новым. Это независимый инструмент проверки и не подключается к Zoom.

## Что осталось подтвердить в Zoom

Для заключения «проверено на реальной встрече» нужен личный Local Test: получить настоящее RTMS аудио на Windows, сверить два разных source ID при одинаковых именах, переименование/повторный вход, остановку и reconnect, сохранить экспорты и проверить заметный разрыв соединения. Отдельно проверить язык, перекрывающихся говорящих, фактическую задержку от Zoom и ограничения тарифа. До такого прогона успех локальных тестов не считается приёмкой Zoom-интеграции.
