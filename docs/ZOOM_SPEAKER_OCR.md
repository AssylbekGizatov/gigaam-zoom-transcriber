# Отображаемые имена Zoom через локальное OCR

Этот режим добавлен для случая, когда desktop Zoom не раскрывает активного
говорящего через UI Automation. Он читает пиксели выбранной области имени
в Speaker View с помощью встроенного Windows.Media.Ocr. Аудио по-прежнему
распознаёт локальная GigaAM; модель diarization не устанавливает имена.
Сетевых OCR-сервисов, платных API и загрузок с Hugging Face нет.

## Что показал тест пользователя

Среда: Windows 11 `10.0.26100.9711`, Zoom Workplace `7.1.5 (43453)`,
Python 3.13 x64, запуск `py -3.13 app.py`. Group Policy запрещает запуск
`.venv\Scripts\python.exe` с WinError 1260. Модели уже доступны через
GitHub Release `models-v1`.

Пользователь сообщил о семи видимых окнах Zoom. Обход всех окон превышал
512 элементов / 0,8 секунды (`uia_scan_incomplete`). Обход только Zoom Meeting
завершался `uia_missing`. В Speaker View с тремя участниками ControlViewWalker
и RawViewWalker нашли по восемь элементов; при попеременной речи двух удалённых
участников изменений проверяемых свойств не было.

Эти данные не доказывают отсутствие любых accessibility-интерфейсов в Zoom,
но расширение регулярных выражений не создаст отсутствующий в наблюдениях сигнал.
UIA теперь ограничен подходящим окном встречи. Для данной ситуации предусмотрен
отдельный режим OCR, который включается пользователем после настройки области.
**Новый путь ещё требует проверки на этой Windows/Zoom-сборке.** Автотесты
проверяют логику на синтетических данных и не являются тестом настоящей встречи.

## Установка без virtual environment

В терминале в корне репозитория, с тем же Python, которым запускается приложение:

```powershell
py -3.13 -m pip install --user -r requirements-zoom-ocr.txt -c constraints.txt
py -3.13 scripts/acquire_model.py --check
py -3.13 app.py
```

Это дополнение к уже установленному desktop-приложению. Полные команды чистой
установки находятся в [README](../README.md#корпоративный-windows-python-313-без-virtual-environment).
Не запускайте `.venv`, `setup.ps1` или `start.ps1` для этого варианта;
обходить Group Policy и менять ExecutionPolicy не нужно.

OCR-пакеты закреплены на WinRT 3.2.1. Через метаданные PyPI проверено наличие
`cp313-cp313-win_amd64` wheels для runtime, Foundation, Foundation.Collections,
Globalization, Media.Ocr, Graphics.Imaging и Storage.Streams, а также для
Pillow 12.3.0. Это проверка доступности установочных файлов, не испытание
нативных API Windows. Не используйте free-threaded Python (`cp313t`) или ARM64
как эквивалент указанной x64-среды.

Windows должен уже иметь OCR-компонент нужного языка. Выберите `ru-RU` для
кириллицы или `en-US` для латиницы. Приложение не загружает языковые компоненты
Windows; отсутствие языка нужно согласовать с IT. Не следует предполагать,
что установка только языка интерфейса Windows автоматически добавила OCR.
Возможности OCR зависят от языков, установленных на конкретной машине;
точность казахских букв и смешанных имён необходимо проверить отдельно.

## Настройка области имени

1. Войти в встречу с тремя участниками. Включить **Speaker View** и отображение
   имён участников. Отключить pin/закрепление и spotlight; закрыть демонстрацию
   экрана. В основном видео должен автоматически меняться именно говорящий.
2. В приложении включить чтение имён и выбрать режим **OCR**. Выбрать язык OCR.
3. Запустить выбор области имени и следовать подсказке для переключения в Zoom.
   На предварительном изображении выделить прямоугольник только с именем
   основного участника. Не включать список участников, субтитры, аватар с крупным
   именем, микрофон, toolbar или вторую строку. Оставить небольшие поля вокруг
   букв и место для более длинных имён.
4. Сохранить область. Координаты `x,y,width,height` нормализованы относительно
   клиентской области окна Zoom; они сохраняются в настройках. Изображение
   используется только в оперативной памяти, в файл не записывается.
5. Отключить различение голосов, если нужны только отображаемые имена. Для OCR
   модель CAM++ не нужна. Нажать «Начать», подтвердить условия Speaker View,
   затем вернуть Zoom на передний план.
6. Дать двум удалённым участникам по очереди говорить длинными репликами.
   При открытии окна транскрибатора вместо Zoom чтение имени приостанавливается;
   после возвращения Zoom новые наблюдения возобновляются. Текст продолжает
   распознаваться независимо от доступности имени.

ROI хранится в полях `zoom_name_mode="ocr"`, `zoom_ocr_region="x,y,width,height"`
и `zoom_ocr_language`, например `ru-RU`. Размер клиентской области в физических
пикселях сохраняется в `zoom_ocr_client_size="width,height"`. Несовпадение размера
вызывает `ocr_recalibration_required`: выберите область повторно. Режим `uia` оставлен для клиентов,
которые предоставляют явную метку активного говорящего. Автоматического перехода
к OCR произвольной области экрана нет.

После изменения размера, масштаба, компоновки Zoom, панели участников или
расположения видео повторно проверьте область; относительные координаты
не гарантируют правильное место подписи в новой компоновке. После появления
pin/spotlight, перехода в Gallery View или демонстрацию экрана остановите OCR
и заново настройте его в поддерживаемом виде. Программа не может надёжно
обнаружить эти состояния только по изображению имени.

## Как имя связывается с текстом

Наблюдение содержит время снимка по монотонным часам, имя, локальный ID и
признак `ocr_speaker_view_hint`. Имя принимается после повторного совпадения
в последовательных снимках. Пустое распознавание, несколько строк,
усечённая подпись и невалидная область не продлевают предыдущее имя.

История наблюдений используется по времени аудио и словам GigaAM. Имя,
появившееся после фразы, не назначается ей задним числом. Смена имени, разрыв
наблюдений или истечение срока годности оставляет соответствующие слова
неопределёнными. Для OCR граница переключения имеет защитный интервал 1 с с каждой стороны
слова (опрос каждые 0,75 с); короткие реплики
могут остаться без подписи. Последнее изображённое Zoom имя в паузе само по себе
не доказывает, что человек говорит: текст в тишине создавать не следует.

Это чтение **отображаемого имени**, а не Zoom participant ID и не выделенный
аудиопоток участника. В Speaker View Zoom может переключать видео с задержкой;
OCR тоже может устойчиво ошибиться в буквах. Два участника с одинаковой
подписью неразличимы в OCR, а переименование создаёт другой локальный источник.
Не используйте его ID для подтверждения личности. Pin/spotlight, общий
микрофон, одновременная речь и другой звук на том же WASAPI-выходе могут дать
неверную связь, даже когда имя прочитано правильно. Неопределённые участки
и ошибки можно подписать вручную после сеанса.

## Диагностика

Интерфейс показывает имя либо причину отсутствия наблюдения. Проверьте сначала
само видимое имя Zoom, передний план окна, выбранную область и язык Windows OCR.

| Ситуация | Что делать |
|---|---|
| UIA возвращает `uia_missing` | Использовать настроенный OCR при выполнении условий Speaker View. |
| Несколько подходящих окон встречи | Оставить одно подходящее окно; не угадывать нужную встречу. |
| Zoom свёрнут или не на переднем плане | Вернуть окно встречи; захват текста не требуется останавливать. |
| OCR-зависимости недоступны | Установить `requirements-zoom-ocr.txt` через тот же `py -3.13`. |
| OCR-язык недоступен | Выбрать уже установленный язык или согласовать его компонент с IT. |
| Пустое/многострочное/обрезанное имя | Повторить выделение области, проверить отображение имён в Zoom. |
| Первое наблюдение или имя изменилось | Дождаться повторного совпадения; до него имя неизвестно. |
| OCR завис или завершился с ошибкой | Имя неизвестно; аудио продолжает работу, процесс наблюдения ограничен таймаутом. |

Без запуска ASR можно проверить наблюдатель из терминала:

```powershell
py -3.13 scripts/probe_zoom_names.py --list-languages
py -3.13 scripts/probe_zoom_names.py --mode uia --duration 15
py -3.13 scripts/probe_zoom_names.py --mode ocr --region .02,.85,.25,.05 --language ru-RU --client-size 1920,1080 --duration 30
```

В последней команде координаты и размер — **пример**, замените их значениями
своей калибровки. `1920,1080` означает физический размер клиентской области
Zoom, не размер монитора. Во время проверки переключитесь в Zoom: терминал
не должен оставаться активным. Скрипт печатает JSON с временем наблюдения,
именем и причиной; не сохраняет изображения или аудио и не вызывает сеть.
Не публикуйте вывод с частными именами. `--list-languages` перечисляет
установленные OCR-языки; если список пуст, нужен компонент Windows OCR.

Снимки встреч не нужны для публикации диагностического отчёта. Достаточно
версий Windows/Zoom/Python, OCR-языка, режима окна и кодов ошибок. Проверку
имён выполняйте локально; частные имена/текст не помещайте в публичный GitHub.

## Рассмотренные способы

| Способ | Применимость здесь |
|---|---|
| UI Automation | Бесплатно и без OCR; требует реально изменяющейся явной метки. В сообщённом тесте её не обнаружено. |
| MSAA / дополнительные accessibility-свойства | Могут быть полезны в отдельной диагностике; наличие имени ещё не доказывает активную речь. Для данной сборки подтверждённого сигнала нет. |
| Windows OCR выбранной области | Бесплатно, локально, работает с видимым текстом; требует настройки и поддерживаемого режима окна. Реализован как отдельная опция. |
| Zoom Meeting SDK | Интерфейсы участника относятся к собственному SDK-клиенту; это не готовое подключение к произвольному уже открытому desktop Zoom. Требует другого решения и проверки условий SDK. |
| RTMS | Отдельный интеграционный путь с требованиями доступа и возможной тарификацией; не нужен для этого исправления. |
| Имена из голосовой diarization | Номера голосовых кластеров не содержат отображаемых имён Zoom. Не используется для определения реальных имён. |

Основные справочные API:
[Windows.Media.Ocr](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine),
[PyWinRT](https://pywinrt.readthedocs.io/),
[Zoom Meeting SDK](https://developers.zoom.us/docs/meeting-sdk/),
[RTMS](https://developers.zoom.us/docs/rtms/).
Предыдущие исследования и ссылки сохранены в [RESEARCH_ZOOM_CAPTURE](RESEARCH_ZOOM_CAPTURE.md).

Пошаговая ручная приёмка находится в [DESKTOP_TESTING](DESKTOP_TESTING.md#приёмка-ocr-на-windows-11-и-zoom-715).
