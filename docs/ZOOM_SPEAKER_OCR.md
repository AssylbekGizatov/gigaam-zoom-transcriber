# Имена Zoom через локальное Windows OCR

OCR читает отображаемую строку имени основного Speaker View. Он не зависит
от UI Automation Zoom и не пытается вывести имя из тембра голоса. GigaAM
распознаёт звук, а история наблюдений связывает слова с именем по времени.
Все компоненты включены в `requirements-desktop.txt`; отдельного режима
установки OCR нет.

## Первый запуск

Установите зависимости из обычного CMD в корне исходников:

```bat
py -3.13 -m pip install --user -r requirements-desktop.txt
py -3.13 app.py
```

В мастере первого запуска проверьте GigaAM, обновите список OCR-языков,
проверьте окно Zoom, выделите область имени и выберите папку текста.
Если калибровка пропущена, транскрипция может работать с неизвестным именем.
Настройки сохраняются; мастер не требует создания virtual environment или
входа в отдельный аккаунт.

Windows должен уже иметь OCR-компонент нужного языка. В подтверждённой
конфигурации русский тег — `ru`, английский — `en-US`; выбирайте точный тег
из списка установленных языков. Режим `auto` сначала ищет русский OCR, затем
`en-US`, затем первый доступный язык. Для кириллицы и смешанных
имён проверьте установленный язык и точность букв вручную. Приложение не
скачивает Windows language packs; при отсутствии нужного компонента обратитесь
к IT. Нет внешней OCR-модели, Tesseract.exe или облачного запроса.

## Выбор области имени

1. Откройте одну встречу Zoom, включите Speaker View и отображение имён.
   Уберите pin/закрепление, spotlight и демонстрацию экрана. Основное видео
   должно само меняться при смене говорящего.
2. Запустите выбор области. Приложение временно освобождает окно Zoom для
   калибровки. Выделите **только строку имени** основного участника, с небольшими
   полями и запасом по ширине для более длинной подписи.
3. Не включайте список участников, субтитры, крупное имя аватара, вторую строку,
   иконки или toolbar. Проверьте предварительное изображение и результат OCR.
4. Сохраните калибровку. Область хранится в относительных координатах клиентской
   части Zoom вместе с её геометрией; снимок автоматически не сохраняется.
5. Начните сеанс. Оставьте Zoom развёрнутым; после калибровки его может
   перекрывать другое приложение при успешном захвате самого окна.

## Захват окна и перекрытие

Приложение последовательно пробует **Windows Graphics Capture (WGC)**,
**PrintWindow**, затем **screen DC**. Первые два способа запрашивают изображение
окна Zoom и могут читать его, когда сверху находится другое приложение.
Передний план Zoom не обязателен. Это требует работоспособного оконного
захвата на конкретной Windows/GPU-конфигурации; одно наличие WGC в системе
не гарантирует пригодного кадра.

Если WGC недоступен, завис или вернул пустой кадр, используется PrintWindow.
Если он тоже не дал пригодного кадра, screen DC допускается только при полностью
видимой и неперекрытой области имени — до и после снимка. Текст чужого окна
не должен распознаваться как имя Zoom. При перекрытии и отказе обоих оконных
способов наблюдение остаётся без имени, причина — `ocr_region_occluded`.
Восстановленная позднее подпись короткой реплики отдельно помечается как
вывод по соседям, а не успешный захват перекрытой области.
Нативная попытка ограничена таймаутом 2,5 секунды. После пустого оконного
кадра повторная попытка разрешается через 2 секунды, после других отказов —
через 30 секунд; работающий следующий способ продолжает использоваться.

**Свёрнутый Zoom не поддерживается:** кадр отвергается с
`ocr_window_minimized`. Не путайте перекрытое окно с минимизированным.
Захват и OCR выполняются в ограниченных по времени вспомогательных процессах;
ошибка захвата не должна останавливать аудио. Скриншоты автоматически
не сохраняются. При WGC Windows может показывать системную рамку захвата;
приложение не обходит решения Windows о доступности этого режима.

Относительная область следует за окном. Изменение размера, DPI, монитора или
HWND сбрасывает подтверждение имени; после него нужны новые совпадающие
наблюдения. Отклонение соотношения сторон от калибровки более чем на 12%
требует повторного выделения области. Панели и компоновка Zoom могут сдвинуть
строку без изменения размера окна — тогда повторно проверьте область.

Gallery View, pin, spotlight и share не поддерживаются. Одни пиксели имени
не позволяют надёжно определить эти режимы автоматически. Если режим
изменился, прекратите чтение имени и вернитесь к поддерживаемому Speaker View.

## Как имя становится подписью

Каждое наблюдение содержит время снимка, имя, локальный ID и признак
`ocr_speaker_view_hint`. Повторное чтение подтверждает имя. Пустой кадр,
многострочная или обрезанная подпись, отказ захвата и невалидная геометрия не
продлевают предыдущее имя. Таймаут чтения изолирован от аудио и интерфейса.

Обработка OCR занимает время. Наблюдение относится к времени кадра, а не
моменту получения OCR-ответа или завершения ASR. Для слова оценивается окно
от **500 мс до начала** до **1500 мс после окончания**, с ограничением по
границам удалённого речевого участка и следующему участку. Это позволяет
учесть небольшое запаздывание подписи Zoom. Одно позднее, неподтверждённое
имя само по себе не является достаточной опорой. Первое чтение может
участвовать лишь после последующего подтверждения той же строки. Старое
неизменное имя, оставшееся через паузу, не назначается началу нового речевого
участка. Действительно новое имя может подтвердиться уже после короткой
фразы, но до следующего речевого участка. Имя не продолжается за последнее
фактическое наблюдение.

Поддержку кандидата дают интервалы между совпадающими наблюдениями, расстояние
между которыми не превышает 2 секунд. Веса — длительность поддержки,
умноженная на confidence, если адаптер его предоставил; без confidence
используется только длительность. Это не вероятность личности. Нужно не
менее 200 мс взвешенной поддержки. При нескольких кандидатах победителю нужно
не менее 75% суммарного веса, а поздняя противоречащая подпись блокирует
назначение прежнего имени. На смешанном переходе результат может остаться
«Неизвестно» даже при большом весе одного кандидата.

Последние наблюдения хранятся около 60 секунд. Интервалы, необходимые уже
принятым аудиобуферам и очереди ASR, сохраняются дополнительно до обработки.
Поэтому задержка модели не должна подменять старое имя текущим и не должна
сама по себе стирать доказательства для принятой фразы. При нехватке будущих
наблюдений ASR-поток может подождать до 2,5 секунды один раз на окно
декодирования, только если уже есть полезные OCR-данные. Ожидание хвоста при
остановке тоже ограничено 2,5 секунды; GUI и захват звука не ждут этого поиска.

Тишина, известное пересечение локального микрофона с удалённой речью,
пересекающиеся таймкоды удалённых слов и явные отказы чтения не получают
прямую подпись. Временное отсутствие читаемого имени учитывается отдельно:
последующее восстановление короткого пропуска описано ниже.

Порог звуковой активности отсеивает тишину, но не распознаёт число голосов
в общем WASAPI-миксе. Два удалённых участника, говорящие одновременно или
сменяющие друг друга при неизменной строке имени Zoom, неотличимы для этого
правила. Правильное распознавание текста имени не гарантирует правильного
говорящего.

Локальный ID не является Zoom participant ID. Два человека с одинаковым
отображаемым именем неразличимы, переименование создаёт другую локальную
подпись. OCR может устойчиво ошибиться в буквах. Zoom может переключать
Speaker View позже начала речи. Оставшееся на экране имя после фразы не
доказывает речь во время тишины. Общий микрофон, одновременные голоса и звук
другого приложения на том же WASAPI-выходе могут дать неверную связь даже
при правильно прочитанном имени.

## Имя, восстановленное по соседним репликам

Короткая удалённая реплика без подписи может получить имя из двух соседних
реплик, если её длительность **меньше 1,5 секунды**, расстояние до каждого
соседа **меньше 2 секунд**, а оба соседа имеют одинаковые локальный ID и имя
из непосредственного OCR в том же сеансе. Результат отмечается
`inferred_gap_fill` и пометкой «имя восстановлено по соседним репликам».
Это вывод по окружению, а не распознавание имени внутри пропуска.

Восстановление разрешено для нехватки наблюдений и краткого отсутствия
читаемого имени (`ocr_name_missing` / `ocr_region_occluded`). Оно не перекрывает
подтверждённую тишину, конфликт имён, известное наложение, разрыв аудио или
жёсткий отказ OCR, например timeout. Микрофон, ручные подписи, неподтверждённые имена
и уже восстановленные реплики не служат опорой; цепочка догадок не строится.
Длинный пропуск и разные имена по сторонам остаются «Неизвестно».

Исходная причина отсутствия имени остаётся в `attribution_reason`, а вывод
по соседям отличает `attribution=inferred_gap_fill`. Лог `attribution_decision`
отражает прямое решение при обработке ASR; последующее восстановление
проверяйте по итоговой метке реплики. Текст и таймкоды сохраняются.
Ручная правка имеет приоритет (`manual`),
а появившееся противоречие или поздняя реплика вызывает пересмотр восстановления.
В старых журналах без причины отсутствия имени оно автоматически не домысливается.

## Диагностика без ASR

```bat
py -3.13 scripts/probe_zoom_names.py --list-languages
py -3.13 scripts/probe_zoom_names.py --region .02,.85,.25,.05 --language ru --client-size 1920,1080 --duration 30
```

Координаты и размер в примере замените своими. `--region` — `x,y,width,height`
в долях клиентской области Zoom. `--client-size` — её физические пиксели,
не размер монитора. Диагностика содержит время, принятую подпись, код причины,
`capture_method` (`wgc`, `printwindow`, `screen_dc`) и `capture_attempts` —
список `{method, evidence}` с причинами перехода к следующему способу.
`capture_ok` означает успех, `capture_backoff` — временный пропуск ранее
отказавшего способа. Пустой `capture_method` означает, что
пригодный кадр не получен. Непустое значение при ошибке может обозначать
последний испробованный способ; успех подтверждается `capture_ok`, а не одним
названием способа.
Для подробного локального разбора добавьте `--dump-ocr-text`: он включает
сырые строки OCR, число элементов, время обработки и геометрию.

Не публикуйте необезличенный вывод: в нём могут быть имена и другой текст
выбранной области. Полный кадр для диагностики можно явно запросить параметром
`--save-debug-frame "C:\LocalDebug\zoom.png"`; это сохраняет **один** кадр
только по данной команде. Для всего окна используется `--region 0,0,1,1`.
Такой кадр может содержать лица и частную переписку; обычная работа приложения
и обычный запуск probe не создают файлы изображений.

| Код / состояние | Проверка |
|---|---|
| `zoom_window_not_found` | Открыта ли видимая встреча Zoom? |
| `zoom_window_ambiguous` | Есть несколько подходящих окон; оставьте одно. |
| `ocr_window_minimized` | Разверните окно встречи. |
| `ocr_region_occluded` | Оконные способы не дали кадр, а screen DC закрыт другим окном; уберите перекрытие и проверьте `capture_attempts`. |
| `ocr_recalibration_required` | Соотношение сторон существенно изменилось; повторите выделение. |
| `ocr_capture_blank` | Захват пустой/однородный; проверьте видимость и выбранную область. |
| `ocr_dependency_missing` | Выполните единую установку через тот же `py -3.13`. |
| `ocr_language_unavailable` | Выберите установленный язык либо согласуйте компонент с IT. |
| `ocr_name_missing` / `ocr_name_clipped` | Проверьте границы, поля, показ имён и отсутствие нескольких строк. |
| `ocr_confirming` | Ожидание повторного чтения имени. |
| `ocr_timeout` / `ocr_stale` | OCR не вернул свежее наблюдение; текст продолжает работать. |

Коды и точные дополнительные поля probe могут расширяться. Используйте
`py -3.13 scripts/probe_zoom_names.py --help` для текущего синтаксиса.

## Проверка на конкретном Zoom

Исходный тест пользователя не нашёл изменяющихся accessibility-свойств
в Zoom 7.1.5 (43453); это причина перехода к видимому тексту. Он не доказывает,
что новый OCR уже прошёл аппаратную проверку. Для Windows `10.0.26100.9974`
нужен [сценарий приёмки](DESKTOP_TESTING.md) с A/B, паузами, переименованием,
перекрытием, масштабированием и экспортом. Покрытие имён и точность нужно
считать отдельно.
