# Имена Zoom через локальное Windows OCR

OCR читает отображаемую строку имени основного Speaker View. Он не зависит
от UI Automation Zoom и не пытается вывести имя из тембра голоса. GigaAM
распознаёт звук, а история наблюдений связывает слова с именем по времени.
Все компоненты включены в `requirements-desktop.txt`; отдельного режима
установки OCR нет.

## Первый запуск

Установите зависимости из обычного CMD в корне исходников:

```bat
py -3.13 -m pip install --user -r requirements-desktop.txt
py -3.13 app.py
```

В мастере первого запуска проверьте GigaAM, обновите список OCR-языков,
проверьте окно Zoom, выделите область имени и выберите папку текста.
Если калибровка пропущена, транскрипция может работать с неизвестным именем.
Настройки сохраняются; мастер не требует создания virtual environment или
входа в отдельный аккаунт.

Windows должен уже иметь OCR-компонент нужного языка. В подтверждённой
конфигурации русский тег — `ru`, английский — `en-US`; выбирайте точный тег
из списка установленных языков. Режим `auto` сначала ищет русский OCR, затем
`en-US`, затем первый доступный язык. Для кириллицы и смешанных
имён проверьте установленный язык и точность букв вручную. Приложение не
скачивает Windows language packs; при отсутствии нужного компонента обратитесь
к IT. Нет внешней OCR-модели, Tesseract.exe или облачного запроса.

## Выбор области имени

1. Откройте одну встречу Zoom, включите Speaker View и отображение имён.
   Уберите pin/закрепление, spotlight и демонстрацию экрана. Основное видео
   должно само меняться при смене говорящего.
2. Запустите выбор области. Приложение временно освобождает окно Zoom для
   калибровки. Выделите **только строку имени** основного участника, с небольшими
   полями и запасом по ширине для более длинной подписи.
3. Не включайте список участников, субтитры, крупное имя аватара, вторую строку,
   иконки или toolbar. Проверьте предварительное изображение и результат OCR.
4. Сохраните калибровку. Область хранится в относительных координатах клиентской
   части Zoom вместе с её геометрией; снимок автоматически не сохраняется.
5. Начните сеанс. Область имени должна оставаться видимой и неперекрытой.

**Передний план Zoom не обязателен**, если его выбранная область видна и не
закрыта другим окном. Свёрнутое, скрытое, частично вне монитора или перекрытое
имя не используется. Перемещение в пределах того же монитора допустимо;
изменение размера, DPI, монитора или окна сбрасывает подтверждение имени,
после чего нужны новые совпадающие наблюдения. Отклонение соотношения сторон
от калибровки более чем на 12% требует повторного выделения области.
Панели и компоновка Zoom могут сдвинуть строку без изменения размера окна —
в таком случае пользователь должен заново проверить область.

Gallery View, pin, spotlight и share не поддерживаются. Одни пиксели имени
не позволяют надёжно определить эти режимы автоматически. Если режим
изменился, прекратите чтение имени и вернитесь к поддерживаемому Speaker View.

## Как имя становится подписью

Каждое наблюдение содержит время снимка, имя, локальный ID и признак
`ocr_speaker_view_hint`. Повторное чтение подтверждает имя. Пустой кадр,
многострочная или обрезанная подпись, перекрытие и невалидная геометрия не
продлевают предыдущее имя. Таймаут чтения изолирован от аудио и интерфейса.

Обработка OCR занимает время; срок свежести ограничен и учитывает измеренную
задержку. Поэтому задержка Windows OCR не должна превращать каждый корректный
ответ в устаревший. При этом результат относится к времени снимка, а не
моменту его возвращения. История привязывает слова GigaAM к наблюдениям во
время аудио. Каждому подписанному слову нужны одинаковые наблюдения до его
начала и после его окончания в пределах того же участка слышимого удалённого
звука. Между ними не должно быть конфликтующего имени, unknown или слишком
большого разрыва. Одного позднего имени недостаточно. При тишине, известном
пересечении локального микрофона с удалённой речью или пересекающихся таймкодах
удалённых слов подпись остаётся «Неизвестно».

Порог звуковой активности отсеивает тишину, но не распознаёт число голосов
в общем WASAPI-миксе. Два удалённых участника, говорящие одновременно или
сменяющие друг друга при неизменной строке имени Zoom, неотличимы для этого
правила. Правильное распознавание текста имени не гарантирует правильного
говорящего.

Локальный ID не является Zoom participant ID. Два человека с одинаковым
отображаемым именем неразличимы, переименование создаёт другую локальную
подпись. OCR может устойчиво ошибиться в буквах. Zoom может переключать
Speaker View позже начала речи. Оставшееся на экране имя после фразы не
доказывает речь во время тишины. Общий микрофон, одновременные голоса и звук
другого приложения на том же WASAPI-выходе могут дать неверную связь даже
при правильно прочитанном имени.

## Диагностика без ASR

```bat
py -3.13 scripts/probe_zoom_names.py --list-languages
py -3.13 scripts/probe_zoom_names.py --region .02,.85,.25,.05 --language ru --client-size 1920,1080 --duration 30
```

Координаты и размер в примере замените своими. `--region` — `x,y,width,height`
в долях клиентской области Zoom. `--client-size` — её физические пиксели,
не размер монитора. Обычный вывод содержит время, принятую подпись и код причины.
Для подробного локального разбора добавьте `--dump-ocr-text`: он включает
сырые строки OCR, число элементов, время обработки и геометрию.

Не публикуйте необезличенный вывод: в нём могут быть имена и другой текст
выбранной области. Полный кадр для диагностики можно явно запросить параметром
`--save-debug-frame "C:\LocalDebug\zoom.png"`; это сохраняет **один** кадр
только по данной команде. Для всего окна используется `--region 0,0,1,1`.
Такой кадр может содержать лица и частную переписку; обычная работа приложения
и обычный запуск probe не создают файлы изображений.

| Код / состояние | Проверка |
|---|---|
| `zoom_window_not_found` | Открыта ли видимая встреча Zoom? |
| `zoom_window_ambiguous` | Есть несколько подходящих окон; оставьте одно. |
| `ocr_window_minimized` | Разверните окно встречи. |
| `ocr_region_occluded` | Уберите окно, перекрывающее выбранную строку. |
| `ocr_recalibration_required` | Соотношение сторон существенно изменилось; повторите выделение. |
| `ocr_capture_blank` | Захват пустой/однородный; проверьте видимость и выбранную область. |
| `ocr_dependency_missing` | Выполните единую установку через тот же `py -3.13`. |
| `ocr_language_unavailable` | Выберите установленный язык либо согласуйте компонент с IT. |
| `ocr_name_missing` / `ocr_name_clipped` | Проверьте границы, поля, показ имён и отсутствие нескольких строк. |
| `ocr_confirming` | Ожидание повторного чтения имени. |
| `ocr_timeout` / `ocr_stale` | OCR не вернул свежее наблюдение; текст продолжает работать. |

Коды и точные дополнительные поля probe могут расширяться. Используйте
`py -3.13 scripts/probe_zoom_names.py --help` для текущего синтаксиса.

## Проверка на конкретном Zoom

Исходный тест пользователя не нашёл изменяющихся accessibility-свойств
в Zoom 7.1.5 (43453); это причина перехода к видимому тексту. Он не доказывает,
что новый OCR уже прошёл аппаратную проверку. Для Windows `10.0.26100.9974`
нужен [сценарий приёмки](DESKTOP_TESTING.md) с A/B, паузами, переименованием,
перекрытием, масштабированием и экспортом. Покрытие имён и точность нужно
считать отдельно.
