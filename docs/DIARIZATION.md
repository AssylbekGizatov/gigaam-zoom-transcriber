# Локальные номера говорящих: экспериментальный режим

Этот режим группирует похожие голоса в смешанном звуке Zoom. Он работает на CPU,
без аккаунта, ключей, облачного распознавания и сохранения аудиозаписи. Результат —
«Говорящий 1 (по голосу)», а не установленная личность и не настоящий Zoom ID.
Режим включается отдельно: качество в реальной встрече ещё не подтверждено.

## Однократная подготовка

Из корня проекта в виртуальном окружении:

```powershell
python -m pip install -r requirements-diarization.txt
python scripts/download_diarization.py
```

Загрузка модели — единственный сетевой шаг этого модуля. `SherpaSpeakerEmbedder`
не скачивает файлы автоматически и не отправляет аудио. Модель помещается в
`models/diarization/campplus.onnx`; папка исключена из Git. Повреждённая модель
или несовпадающая контрольная сумма не загружаются. Нужны
`sherpa-onnx==2.0.1` и `sherpa-onnx-core==2.0.1`.

## Модель и лицензия

экспорт ONNX из официального release sherpa-onnx. Файл занимает
28 281 164 байта. SHA-256:

## Как это работает

`OnlineDiarizer.analyze(samples16k, start_seconds)` получает float32 mono 16 кГц.
Он обрабатывает окна по 3 секунды с шагом 1 секунда. В памяти остаётся менее
3 секунд аудио и до 16 небольших векторов голосов. Текст не используется для
определения номера голоса. Слабый сигнал, клиппинг, неоднозначное сходство и
несогласованные половины нового окна дают unknown.

`DiarizationTimeline.analyze_window(source_id, samples, rate, start_seconds)`
принимает пересекающиеся окна ASR и пропускает повторные семплы. Он анализирует
только смешанный источник `local:remote…`, сохраняя не более 120 секунд / 256
последних интервалов. `resolve(start, end)` возвращает голос только при непрерывном
покрытии слова одним достаточно уверенным кластером. Пропуск, смена номера или
неопределённость оставляют имя неизвестным. Таймкоды относительны началу локального
захвата, как и в ASR-конвейере.

Идентификаторы имеют вид `local:voice:001`. Поле `confidence` — сходство векторов,
**не вероятность правильной идентификации**. Для нового кластера это согласованность
двух половин окна. Центроиды существуют только в текущей сессии; приложение не
создаёт постоянную базу биометрических профилей. Локальные кластеры могут ошибочно
разделить одного человека или объединить разных людей.

## Что измерено

[Машинный отчёт CAM++](evidence/desktop-diarization-campplus.json) получен на пользовательском
Windows 11, 8 логических CPU, 8 029 MiB RAM. Настоящая ONNX-модель обработала
48,305 секунды разрешённой публичной речи за 3,442 секунды: **RTF 0,0713**.
Медианное время добавления очередного окна ASR — 0,476 с, максимум — 0,706 с.
Режим использует один inference-поток; во время ускоренного прогона занял примерно
12,60% общей CPU-мощности. Это burst-прогон, не средняя нагрузка во время встречи.

Загрузка модели заняла 1,587 с. Пиковая sampled RSS загрузки — 106,2 MiB, прирост
к базовому Python-процессу — 66,9 MiB. Во время обработки peak RSS — 120,1 MiB.
Это отдельный процесс измерения без одновременно загруженной GigaAM: суммарную
нагрузку приложения нужно смотреть в интеграционном отчёте desktop pipeline.

Казахский, русский и английский публичные клипы получили три разных доминирующих
кластера; точное повторение казахского клипа после пауз сохранило первоначальный
номер. **Это данные разработки, не независимая проверка качества**: выбор модели
выполнялся на этих же трёх клипах. Повторение того же WAV не доказывает узнавание
человека на новой речи. Пороги CAM++: совпадение 0,60, создание нового кластера ниже
0,35, отрыв от второго кандидата 0,10, согласованность половин 0,45. Неоднозначность
остаётся unknown. Эти числа не являются универсальными порогами верификации личности.

Предыдущие измерения **не перезаписаны**: [WeSpeaker standalone](evidence/desktop-diarization.json)
получил три кластера после настройки порогов на этих клипах, но
[WeSpeaker через реальный WASAPI и GigaAM](evidence/desktop-loopback-diarization.json)
снова объединил KK и RU в один кластер. Это конкретная неудачная проверка,
показавшая, что одного успешного теста WAV недостаточно. WeSpeaker был заменён
на CAM++; сравнение не доказывает общую точность новой модели.

После этого выполнен [интеграционный прогон CAM++ через настоящий Windows WASAPI,
GigaAM и экспорт](evidence/desktop-loopback-campplus.json). Три публичных клипа
получили три разных номера без обнаруженного объединения между языковыми
фрагментами. При этом покрытие метками осталось ограниченным:

| Публичный фрагмент | Слова с номером голоса | Остальные слова |
|---|---:|---:|
| Казахский | 1 из 9 | 8 unknown |
| Русский | 20 из 26 | 6 unknown |
| Английский | 13 из 17 | 4 unknown |
| Всего | 34 из 52 (65,4%) | 18 unknown |

Это полезнее ошибочного объединения голосов, но **не удовлетворяет требованию
надёжно подписывать каждого говорящего**. Особенно недостаточно покрытие казахского
фрагмента. Поэтому функция остаётся экспериментальной и по умолчанию выключена.
Этот тест использовал воспроизведение публичных файлов, а не живую встречу Zoom.
Суммарная sampled RSS GigaAM + CAM++ достигла около 1 961 MiB, средняя CPU-нагрузка
прогона — 11,94% машины. Задержки готовых сегментов составили 3,625–10,598 с.
Полные параметры и границы измерения сохранены в отдельном отчёте.

Для воспроизведения, с уже подготовленными публичными fixtures из основного
тестирования:

```powershell
python scripts/evaluate_diarization.py --fixtures ПУТЬ_К_ПУБЛИЧНЫМ_FIXTURES
python -m pytest tests/test_diarization.py -q
```

В отчёт не входят аудио, локальные абсолютные пути или личные встречи. Неизвестные
интервалы содержат и тишину; их доля не является DER или точностью диаризации.

## Чего режим не обещает

Здесь нет обученного детектора перекрывающихся голосов. Проверка согласованности
частей окна отсекает некоторые смены говорящего, но одновременная речь может быть
неправильно приписана одному кластеру. Не проверены естественное переключение
языков одним человеком, шумные микрофоны, смена устройства и независимая выборка
казахских/русских/английских встреч. Несколько людей возле общего микрофона также
могут распознаваться неверно. Короткие остатки аудио при завершении намеренно
получают unknown; уже распознанный текст сохраняется.

Поэтому этот модуль — полезный дополнительный ориентир для редактирования
транскрипта, а не доказанный заменитель раздельных потоков Zoom.
